## 学んだこと

### ポリモーフィズム

派生クラスのインスタンスは，基底クラス型の変数やコレクションで扱うことができる．`virtual`メソッドを呼び出すと，変数の型ではなく実際のオブジェクトの型に対応する処理が実行される．

```csharp
List<Shape> shapes = [new Rectangle(), new Triangle(), new Circle()];

foreach (Shape shape in shapes)
{
    shape.Draw();
}
```

### 仮想メンバー

基底クラスのメソッドやプロパティを`virtual`にすると，派生クラスで`override`できる．仮想にできるのはメソッド，プロパティ，イベント，インデクサーで，フィールドは仮想にできない．

```csharp
DerivedClass B = new();
BaseClass A = B;

A.DoWork();
```

この場合，`A`は`BaseClass`型だが，実体は`DerivedClass`なので`DerivedClass`の`DoWork`が呼ばれる．

### 新しいメンバーで基底クラス メンバーを隠ぺいする

`new`を付けると，基底クラスのメンバーをoverrideせずに隠すことができる．`override`と異なり，呼び出されるメソッドはオブジェクトの実際の型ではなく，変数の型で決まる．フィールドやプロパティも同じ名前で隠すことができる．

### 派生クラスで仮想メンバーのオーバーライドを禁止する

`sealed override`を付けると，そのクラスより下の派生クラスで同じ仮想メンバーをoverrideできなくなる．派生クラスで`new`を付けて別のメンバーを宣言することはできる．

### 派生クラスから基底クラスの仮想メンバーにアクセスする

overrideしたメソッドの中で`base`を使うと，基底クラスの実装を呼び出せる．基底クラスの処理に派生クラス独自の処理を加えることができる．

### 例外の概要

例外は`System.Exception`から派生した型で表され，`throw`でスローできる．例外が発生すると，呼び出し履歴をさかのぼって対応する`catch`を探す．対応する処理がなければプログラムはエラーで終了する．

例外を処理してプログラムを既知の状態に戻せない場合は，無理にcatchしない．`System.Exception`をcatchした場合は，必要に応じて`throw;`で再スローする．

### 例外を使用する

`try`で例外が起きる可能性がある処理を囲み，`catch`で処理する例外の型を指定できる．複数の`catch`を使う場合は，具体的な例外から順に並べる．

```csharp
try
{
    result = SafeDivision(a, b);
}
catch (DivideByZeroException)
{
    Console.WriteLine("Attempted divide by zero.");
}
```

`finally`は例外が起きた場合にも実行されるため，ファイルなどのリソースを解放する処理に使える．

## 詰まったこと・分からなかったこと・知らなかったこと

- 基底クラス型の変数から呼び出しても，実際の型のoverrideが実行されること
- `new`で隠したメンバーは，変数の型によって呼び出し先が決まること
- `sealed override`でoverrideを止めた後も，`new`で別のメンバーを宣言できること
- `catch`を具体的な例外から並べる必要があること
- 例外が起きた場合も`finally`が実行されること
