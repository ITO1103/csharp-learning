## 学んだこと

### null許容値型

値型は通常`null`を持てないが，`?`を付けることで`null`を許容できる．

```csharp
int? age = null;
double? price = 9.99;
bool? isActive = null;
```

配列でもnull許容値型を使用できる．

```csharp
int?[] scores = [100, null, 85, null, 72];
```

### null許容値型の値を確認する

`is`を使うことで，nullではない場合だけ値を取り出すことができる．

```csharp
int? temperature = 72;

if (temperature is int degrees)
{
    Console.WriteLine($"Temperature is {degrees}F.");
}
```

`HasValue`を使って値が存在するか確認し，`Value`で実際の値を取得することもできる．

```csharp
int? count = 42;

if (count.HasValue)
{
    Console.WriteLine($"Count is {count.Value}.");
}
```

nullと直接比較することもできる．

```csharp
if (quantity != null)
{
    Console.WriteLine($"Quantity: {quantity.Value}");
}
```

### フォールバックを使用して値を取得する

`GetValueOrDefault()`を使うと，nullの場合にデフォルト値を取得できる．

```csharp
int? rating = null;

int result1 = rating.GetValueOrDefault();
int result2 = rating.GetValueOrDefault(-1);
```

`GetValueOrDefault()`では，引数を指定しなければ型のデフォルト値になり，引数を指定すればその値をフォールバックとして使用する．

`??`でもnullの場合の値を指定できる．

```csharp
int? priority = null;

int effective = priority ?? 0;
```

### null許容値型の算術演算

null許容値型でも通常の算術演算ができる．

```csharp
int? a = 10;
int? b = 20;
int? c = null;

int? sum = a + b;
int? product = a * c;
```

両方に値があれば通常通り計算されるが，どちらかがnullの場合は計算結果もnullになる．

```csharp
Console.WriteLine(product.HasValue);
```

この場合は`false`になる．

### null許容参照型

参照型では，`?`を付けることでnullになる可能性があることを明示できる．

```csharp
string required = "always set";
string? optional = null;
```

`string`はnullではないことを想定し，`string?`はnullになる可能性があることを表す．

```csharp
if (optional is not null)
{
    Console.WriteLine(optional.Length);
}
```

nullではないことを確認すれば，安全にメンバーへアクセスできる．

### 注釈を使用して意図を表現する

クラスのプロパティでも，必須の値と任意の値を`string`と`string?`で表現できる．

```csharp
public sealed class Person(string firstName, string lastName)
{
    public string FirstName { get; } = firstName;
    public string? MiddleName { get; init; }
    public string LastName { get; } = lastName;
}
```

`MiddleName`は存在しない場合があるので`string?`としている．

`ToString()`では三項演算子を使い，`MiddleName`がnullかどうかで出力を変えた．

```csharp
public override string ToString() => MiddleName is null
    ? $"{FirstName} {LastName}"
    : $"{FirstName} {MiddleName} {LastName}";
```

`sealed class`は継承できないクラスを表す．

また，`override`を使うことで親クラスから継承した`ToString()`の動作を上書きできる．

### null状態分析

コンパイラはコードの流れから，変数がnullである可能性を追跡している．

```csharp
string? message = null;
// Console.WriteLine(message.Length);

message = "Hello World!";
Console.WriteLine(message.Length);
```

nullの可能性がある状態で`Length`などへアクセスするとコンパイラは警告を出す．
警告を無視して実際にnullへアクセスすると，実行時に`NullReferenceException`が発生する．

`while`などの条件もコンパイラが分析する．

```csharp
Node? current = start;

while (current is not null)
{
    Console.WriteLine(current.Name);
    current = current.Parent;
}
```

`while`の中では`current`がnullではないことが分かっているため，安全に`Name`へアクセスできる．

### `!`でnull警告を上書きする

`!`を付けることで，値がnullではないことをコンパイラに伝えることができる．

```csharp
string? maybeName = LookUpName("ada");

int length = maybeName!.Length;
```

ただし，`!`は実際の値を変更するものではなく，コンパイラの警告を抑えるだけ．

実際の値がnullであれば，実行時には`NullReferenceException`が発生する．

### APIコントラクトを記述する属性

`NotNullWhen`属性を使うことで，メソッドの戻り値と引数のnull状態の関係をコンパイラに伝えられる．

```csharp
static bool IsPresent([NotNullWhen(true)] string? value) =>
    !string.IsNullOrEmpty(value);
```

`[NotNullWhen(true)]`を付けることで，このメソッドが`true`を返した場合は`value`がnullではないことをコンパイラが判断できる．

```csharp
if (IsPresent(input))
{
    Console.WriteLine(input.Length);
}
```

### 既定の構造体

structを`default`で作成すると，各フィールドには型の既定値が入る．

```csharp
Student s = default;
```

`string`の既定値はnullなので，null非許容として宣言したフィールドでも実際にはnullになる場合がある．

```csharp
public struct Student
{
    public string FirstName;
    public string? MiddleName;
    public string LastName;
}
```

そのため，安全にアクセスする場合は，

```csharp
Console.WriteLine(s.FirstName?.Length ?? -1);
```

のようにできる．

### 参照型の配列

参照型の配列を要素数だけ指定して作成した場合，各要素は最初はnullになる．

```csharp
string[] values = new string[3];
```

この場合，

```text
values[0] → null
values[1] → null
values[2] → null
```

という状態になる．

最初から値を入れて作成すればnullにはならない．

```csharp
string[] initialized = ["a", "b", "c"];
```

### null条件付きメンバーアクセス `?.`

`?.`を使うと，左側がnullではない場合だけメンバーにアクセスする．

```csharp
string? name = null;

int? len = name?.Length;
```

`name`がnullの場合は`Length`へアクセスせず，式全体がnullになる．

複数つなげることもできる．

```csharp
string? upper = input?.Trim()?.ToUpperInvariant();
```

途中でnullになった場合は，それ以降の処理を行わない．

### null条件付きインデクサーアクセス `?[]`

`?[]`を使うと，配列やコレクションがnullではない場合だけ要素へアクセスする．

```csharp
string[]? tags = null;

string? first = tags?[0];
```

`tags`がnullの場合は`tags[0]`へアクセスせず，`first`はnullになる．

### null条件演算子を連結する

`?.`を連結することで，入れ子になったオブジェクトを安全にたどることができる．

```csharp
string? city = order.Customer?.Address?.City;
```

`Customer`や`Address`のどこかがnullなら，そこで処理が止まり式全体がnullになる．

### スレッドセーフなデリゲートの呼び出し

デリゲートでも`?.`を使用できる．

```csharp
EventHandler? clicked = null;

clicked?.Invoke(null, EventArgs.Empty);
```

デリゲートがnullなら何も実行せず，値があれば登録された処理を呼び出す．

### null合体演算子 `??`

`??`を使うと，左側がnullの場合に右側の値を使用できる．

```csharp
string? username = null;

string display = username ?? "Guest";
```

この場合は`username`がnullなので`"Guest"`になる．

### null合体代入演算子 `??=`

`??=`を使うと，変数がnullの場合だけ値を代入できる．

```csharp
List<string>? cache = null;

cache ??= LoadData();
```

すでに値が入っていれば右側は実行されない．

### null条件付き代入

C# 14以降では，`?.`や`?[]`を代入先にも使用できる．

```csharp
AppConfig? config = new AppConfig();

config?.Theme = "dark";
```

`config`がnullではない場合だけ`Theme`に値を代入する．

```csharp
AppConfig? missing = null;

missing?.Theme = "light";
```

この場合は`missing`がnullなので何も代入されない．

### `is null`と`is not null`

`is null`と`is not null`を使って，nullかどうかを確認できる．

```csharp
if (input is null)
{
    Console.WriteLine("No input provided.");
}
```

```csharp
if (value is not null)
{
    Console.WriteLine(value.ToUpper());
}
```

`== null`でも確認できるが，`is null`では演算子のオーバーロードの影響を受けずにnullを確認できる．

### null演算子を組み合わせる

null関連の演算子は組み合わせて使用できる．

```csharp
string city = order?.Customer?.Address?.City ?? "unknown";
```

`?.`で安全にオブジェクトをたどり，途中でnullになった場合は`??`で`"unknown"`を使用する．

## 詰まったこと・分からなかったこと・知らなかったこと

- `string`と`string?`の違い
- null許容コンテキストが何をする設定なのか
- `sealed class`が継承できないクラスを表すこと
- トップレベルステートメントでローカル関数に`public`を付けられないこと
- null状態分析で警告が出ても実行自体は行われること
- nullへ実際にアクセスすると`NullReferenceException`が発生すること
- `while`などのコードの流れからコンパイラがnull状態を判断していること
- `!`はnullをなくすものではなく，コンパイラの警告だけを抑えること
- `[NotNullWhen(true)]`でAPIのnullに関する状態をコンパイラへ伝えられること
- `default`で作成したstructでは，null非許容の参照型フィールドもnullになる場合があること
- `new string[n]`で作成した配列の各要素は最初nullになること
- `?.`と`?[]`の使い方
- `??`と`??=`の違い
- C# 14では`?.`を代入先としても使えること
- null関連の演算子を組み合わせて使用できること

## 振り返り

null安全性について，値型と参照型の両方でnullをどのように扱うのかを学習した．

特に，`?`を付けるだけではなく，コンパイラがコードの流れからnullの状態を分析して警告を出していることが分かった．
実際に警告を無視してnullへアクセスしたところ，実行時に`NullReferenceException`が発生したので，コンパイル時の警告と実行時のエラーの違いも確認できた．

また，`?.`，`?[]`，`??`，`??=`など，nullを安全に扱うための演算子が多く用意されていることを知った．
特に`?.`と`??`を組み合わせることで，入れ子になったオブジェクトでもかなり簡潔にnullを処理できるのは便利そうだと感じた．
