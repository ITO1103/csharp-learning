## 学んだこと

### 宣言パターン

`is`を使って型を確認し，一致した場合はその型の変数として取り出すことができる．

```csharp
if (value is decimal amount)
{
    Console.WriteLine($"Price: {amount:C}");
}
```

`switch`式でも同じように型を判定し，一致した型の変数として使用できる．

```csharp
reading switch
{
    int count => $"Count: {count}",
    double temperature => $"Temperature: {temperature:F1}°C",
    string message => $"Message: {message}",
    _ => "Unsupported reading"
};
```

### 定数パターン

特定の定数値と一致するかを`switch`式で確認できる．

```csharp
command switch
{
    Command.Start => "Starting",
    Command.Stop => "Stopping",
    Command.Pause => "Pausing",
    _ => "Unknown command"
};
```

`Command command`で受け取る型を`Command`に制限し，その値がどの列挙値と一致するかを判定している．

また，`is null`や`is not null`を使ってnullかどうかを確認できる．

```csharp
static bool HasText(string? text) =>
    text is not null;
```

### varパターン

`var`パターンを使うことで，式の結果をその場で変数に受け取り，条件判定や後続処理で再利用できる．

```csharp
ExpressDelivery express
    when EstimateDays(express) is var days && days <= 2
        => $"Arrives in {days} days"
```

この場合，`EstimateDays(express)`の結果を`days`に入れた後，`days <= 2`かを確認している．

### 型パターン

`is`を使って，オブジェクトが特定のクラス，基底クラス，インターフェースに一致するか確認できる．

```csharp
destination is ExpressRouteStop
destination is RouteStop
destination is IRouteStop
```

派生クラスのインスタンスは，その基底クラスや実装しているインターフェースにも一致する．

`abstract`を付けたクラスは直接インスタンス化できず，継承して使用する．

`sealed`を付けたクラスは，それ以上継承できない．

### 複数の型をルーティングする

`switch`式で実行時の型に応じて処理先を分けることができる．

```csharp
request switch
{
    PasswordResetRequest => "Identity queue",
    BillingQuestion => "Billing queue",
    SupportRequest => "General support queue",
    _ => "Intake queue"
};
```

派生クラスは基底クラスにも一致するため，具体的な型を先に書き，より広い基底型を後に書く必要がある．

### 型パラメーターを使った型判定

ジェネリックの型パラメーターを`is`の判定対象として使用できる．

```csharp
if (request is TRequest)
{
    return true;
}
```

呼び出し側で，

```csharp
ContainsRequestOfType<ConfidentialRequest>(incomingRequests);
```

と指定すると，`TRequest`は`ConfidentialRequest`として扱われる．

### プロパティパターン

プロパティ名を指定して，その値が条件に一致するか確認できる．

```csharp
reading is
{
    TemperatureC: > 30,
    HumidityPercent: > 70
};
```

この場合，`TemperatureC`が30より大きく，`HumidityPercent`が70より大きい場合に一致する．

### 位置指定パターン

タプルなどの値を，位置ごとにパターンと照合できる．

```csharp
(signal, crossingIsClear) switch
{
    (PedestrianSignal.Walk, true) => "Cross now",
    (PedestrianSignal.Walk, false) => "Wait for the crossing to clear",
    _ => "Wait for the walk signal"
};
```

プロパティパターンは名前で判定し，位置指定パターンは値の順番で判定する．

### 再帰パターン

プロパティの中にある値までたどって条件を確認できる．

```csharp
DateTime
{
    Date.DayOfWeek:
        DayOfWeek.Saturday or DayOfWeek.Sunday
}
```

この場合，`DateTime`型か確認した後，`Date.DayOfWeek`までたどって土曜日または日曜日かを確認している．

また，空のプロパティパターン`{ }`はnull以外の値に一致する．

```csharp
if (value is not { } nonNullValue)
{
    return "No value";
}
```

`not { }`にすることで，nullの場合に一致させることができる．

### パターンと分岐ステートメントの比較

同じ判定を，`switch`式と通常の`if`文の両方で書くことができる．

```csharp
value switch
{
    DateTime { Date.DayOfWeek:
        DayOfWeek.Saturday or DayOfWeek.Sunday } => "Weekend date",
    DateTime => "Weekday date",
    null => "No date",
    _ => "Not a date"
};
```

通常の`if`文では条件を順番に記述するが，パターンマッチングでは型や状態ごとの条件をまとめて並べて書くことができる．

## 詰まったこと・分からなかったこと・知らなかったこと

- 宣言パターンでは型判定と同時にその型の変数として値を取り出せること
- `switch`式でも型ごとの変数をその場で作れること
- 定数パターンで`enum`の値を直接比較できること
- `var`パターンで計算結果を変数に保存しながら条件判定できること
- `is`では実体の型だけでなく，基底クラスや実装しているインターフェースにも一致すること
- `abstract`は直接インスタンス化できず，継承して使用するクラスであること
- `sealed`はそれ以上継承できないクラスであること
- `switch`で型を判定する場合は，具体的な派生型を基底型より先に書く必要があること
- ジェネリックの型パラメーターを`is`の判定対象として使えること
- プロパティパターンと位置指定パターンの違い
- `{ }`がnull以外の値に一致すること
- 入れ子のプロパティまでたどって条件を指定できること

## 振り返り

宣言パターン，定数パターン，varパターンを通して，`is`や`switch`が単純な値の比較だけでなく，型の判定や変数への取り出しまで同時に行えることを学んだ．

型パターンでは，派生クラスのインスタンスが基底クラスやインターフェースにも一致することや，実行時の型に応じて処理を振り分けられることを確認した．また，`abstract`や`sealed`についても改めて理解できた．

プロパティパターンと位置指定パターンでは，名前を使って条件を指定する方法と，値の位置を使って判定する方法の違いを学んだ．再帰パターンでは，入れ子になったプロパティまでたどって条件を書けることが分かった．
