## 学んだこと

### オブジェクト指向手法の概要

クラス，構造体，レコードの定義は，型が持つメンバーや動作を決める．オブジェクトは，その型の定義に基づいて作られたインスタンス．フィールド，プロパティ，メソッドなどは型のメンバー．

メンバーにはフィールド，定数，プロパティ，メソッド，コンストラクター，イベントなどがある．カプセル化では，アクセス修飾子を使って外部からアクセスできるメンバーを制限する．既定ではメンバーは`private`になる．

クラス，構造体，レコードはインターフェイスを実装でき，ジェネリック型にもできる．レコードでは値による等価性や`with`によるコピーを使える．

### 構造体インスタンスとクラス インスタンス

クラスのインスタンスは`new`で作成する．同じクラスから複数のインスタンスを作成でき，クラスの変数を別の変数に代入するとオブジェクトの参照がコピーされる．そのため，片方の変数からプロパティを変更すると，もう片方から見た値も変わる．

```csharp
Person person1 = new("Leopold", 6);
Person person2 = person1;

person2.Name = "Molly";
person2.Age = 16;
```

構造体は値型なので，別の変数に代入すると値がコピーされる．コピーした側を変更しても，元の変数には影響しない．

```csharp
StructPerson p1 = new("Alex", 9);
StructPerson p2 = p1;

p2.Name = "Spencer";
p2.Age = 7;
```

クラスのインスタンスは，参照がなくなるとガベージコレクションによってメモリが再利用される．また，多くの場合，クラスと構造体のメモリ割り当てによるパフォーマンスの差は大きくない．

### オブジェクト ID と値の等価性

`ReferenceEquals`を使うと，2つのクラス変数が同じオブジェクトを参照しているか確認できる．構造体では，既定の`Equals`で各フィールドの値を比較できる．

クラスの`Equals`や`==`で値を比較する場合は，そのクラスで等価性を定義する必要がある．

```csharp
Console.WriteLine(object.ReferenceEquals(person1, person2));
Console.WriteLine(p2.Equals(p1));
```

### 継承

派生クラスでは，基底クラスの`public`，`protected`，`internal`メンバーを使える．コンストラクターとファイナライザーは継承されない．派生クラスは基底クラスを1つだけ指定できるが，継承は推移する．

```csharp
public class ChangeRequest : WorkItem
{
    protected int OriginalItemId { get; set; }
}
```

`ChangeRequest`では，基底クラスの`WorkItem`から`Update`や`ToString`などを引き継いで使える．派生クラスのコンストラクターから基底クラスのコンストラクターを呼び出すこともできる．

`virtual`メソッドは派生クラスで`override`できる．`abstract`メンバーは，派生クラスが抽象クラスでない場合に実装する必要がある．`sealed`を付けると，それ以上の継承を防げる．派生クラスで同じ名前のメンバーを宣言して基底クラスのメンバーを隠す場合は，`new`を付けて示せる．クラスは基底クラスを1つだけ継承するが，複数のインターフェイスを実装できる．

## 詰まったこと・分からなかったこと・知らなかったこと

- クラスの変数を代入した場合は参照がコピーされ，構造体の変数を代入した場合は値がコピーされること
- `ReferenceEquals`と`Equals`で比較しているものが違うこと
- 継承ではコンストラクターとファイナライザーは引き継がれないこと
- `virtual`，`abstract`，`sealed`，`new`の役割
