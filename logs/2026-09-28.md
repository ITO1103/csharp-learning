## 学んだこと

### nullチェックを追加する

nullになる可能性がある値をそのまま使用すると警告が出る．

```csharp
static int LengthOfMessageUnsafe(string? message)
{
    return message.Length;
}
```

nullチェックを行うことで，その後はコンパイラがnullではないと判断する．

```csharp
static int DereferenceFixed(string? message)
{
    if (message is null)
    {
        return 0;
    }

    return message.Length;
}
```

`?.`と`??`を使って，nullの場合の処理を簡潔に書くこともできる．

```csharp
int length = message?.Length ?? 0;
```

また，

```csharp
if (message is { Length: > 0 })
{
    length = message.Length;
}
```

のように，nullではないこととプロパティの条件を同時に確認するパターンも使用できる．

### 注釈を調整する

メソッドがnullを返す可能性がある場合は，受け取る側も`string?`のようにnullを許容する型にする必要がある．

```csharp
static string? Lookup(string id)
{
    return id switch
    {
        "somebody" => "Alice",
        "bob" => "Bob",
        _ => null
    };
}
```

nullになる可能性がある戻り値を`string`で受け取ると警告が出る．

```csharp
string name = Lookup("nobody");
```

実際にnullになる可能性があるなら，

```csharp
string? name = Lookup("somebody");
```

のように，型の注釈を実際の動作に合わせる．

### null解析属性

メソッドの戻り値と引数のnull状態の関係を，属性を使ってコンパイラに伝えることができる．

```csharp
static bool AttributedIsPresent(
    [NotNullWhen(true)] string? text
) => !string.IsNullOrEmpty(text);
```

`[NotNullWhen(true)]`を付けると，メソッドが`true`を返した場合に，引数がnullではないことをコンパイラが判断できる．

```csharp
if (AttributedIsPresent(text))
{
    Console.WriteLine(text.Length);
}
```

### nullを許容しないメンバーの初期化

nullを許容しないプロパティは，オブジェクトの作成時までに値を設定する必要がある．

コンストラクターで必ず値を渡す方法がある．

```csharp
public class PersonInjected(string name)
{
    public string Name { get; } = name;
}
```

`required`を使って，オブジェクト作成時に指定を必須にすることもできる．

```csharp
public class PersonRequired
{
    public required string Name { get; init; }
}
```

宣言時に初期値を設定することもできる．

```csharp
public class PersonInitialized
{
    public string Name { get; set; } = "John Doe";
}
```

値が存在しない場合もあるなら，無理に初期化せず`string?`にする．

```csharp
public class PersonOptional
{
    public string? Name { get; set; }
}
```

null警告を消すためだけに値を設定するのではなく，その値が必須なのか任意なのかに合わせて型や初期化方法を決める必要がある．

### `string`と`String`

C#の`string`は`System.String`の別名．

```csharp
string a = "hello";
String b = "hello";

Console.WriteLine(typeof(string) == typeof(String));
```

どちらも同じ型を表している．

### 文字列は不変

`string`は，一度作られた文字列オブジェクトそのものの内容を変更できない．

```csharp
string greeting = "hello";

string shouted = greeting.ToUpperInvariant();
```

`ToUpperInvariant()`は元の`greeting`を書き換えるのではなく，新しい文字列を返す．

変数へ別の文字列を代入することはできるが，その場合も元の文字列が変化しているのではなく参照先が変わっている．

文字列を何度も追加する場合は`StringBuilder`を利用できる．

```csharp
using System.Text;

var builder = new StringBuilder();

for (int i = 1; i <= 3; i++)
{
    builder.Append("item ").Append(i).Append(';');
}

string result = builder.ToString();
```

`StringBuilder`は中身を変更しながら文字列を組み立てられるので，何度も連結する場合に便利．

### 通常の文字列リテラルとエスケープシーケンス

通常の文字列では`\`を使って特殊な文字を表現できる．

```csharp
string tabbed = "name:\tAda";
string twoLines = "line 1\nline 2";
string quoted = "She said \"hi\".";
string path = "C:\\src\\app";
```

主なエスケープシーケンスとして，

```text
\n → 改行
\t → タブ
\" → "
\\ → \
\0 → null文字
\uXXXX → Unicode
```

などがある．

C# 13以降では，`\e`でESC文字を表現できる．

```csharp
string esc = "\e[31mError\e[0m: file missing";
```

### 逐語文字列リテラル

`@`を付けると，`\`をエスケープせずにそのまま扱える．

```csharp
string winPath = @"C:\src\app\readme.md";
string pattern = @"\d{3}-\d{4}";
```

Windowsのパスや正規表現などで使用できる．

### 未加工文字列リテラル

`"""`で囲むことで，`"`や`\`をエスケープせずにそのまま記述できる．

```csharp
string json = """
    {
        "name": "Ada",
        "roles": ["admin", "editor"]
    }
    """;
```

JSON，SQL，XML，正規表現などをそのままに近い形で書けるので便利．

通常の文字列，逐語文字列，未加工文字列では，同じ内容を異なる書き方で表現できる．

```csharp
string regular = "{ \"name\": \"Ada\", \"path\": \"C:\\\\src\" }";
string verbatim = @"{ ""name"": ""Ada"", ""path"": ""C:\\src"" }";
string raw = """{ "name": "Ada", "path": "C:\\src" }""";
```

### 複数行の未加工文字列

未加工文字列は複数行をそのまま記述できる．

```csharp
string sql = """
    SELECT id, name
    FROM customers
    WHERE active = 1
    """;
```

開始と終了の`"""`の間に書いた内容が文字列になる．

終了側の`"""`の位置によって，共通のインデントが取り除かれる．

```csharp
string xml = """
        <order id="42">
            <item>book</item>
        </order>
        """;
```

そのため，コード自体はインデントしながら，実際の文字列には余計な空白を含めずに書くことができる．

### 補間文字列

`$`を付けることで，文字列の中に変数や式を埋め込める．

```csharp
string name = "Ada";
int score = 92;

string greeting =
    $"Hello, {name}! Your score is {score}.";
```

書式指定や表示幅の指定もできる．

```csharp
string formatted =
    $"pi = {Math.PI:F3}, padded = |{name,10}|";
```

`$"""`を使うことで，未加工文字列と文字列補間を組み合わせることもできる．

```csharp
string report = $"""
    Player:  {name}
    Score:   {score}
    Updated: {DateTime.UtcNow:yyyy-MM-dd}
    """;
```

### インデックスと`char`

文字列はインデックスを使って1文字ずつ取得できる．

```csharp
string word = "café";

Console.WriteLine(word[0]);
```

この場合，`word[0]`は`char`として取得される．

`foreach`を使って1文字ずつ処理することもできる．

```csharp
foreach (char c in word)
{
    Console.Write($"{c} ");
}
```

また，

```csharp
Console.WriteLine();
```

のように引数なしで`WriteLine()`を呼び出すと，改行だけを出力できることも初めて知った．

### 文字列の等価性

`string`は参照型だが，`==`では参照先が同じかではなく文字列の内容を比較する．

```csharp
string left = "hello";
string right = string.Concat("hel", "lo");

Console.WriteLine(left == right);
```

この場合，作り方が違っても中身が同じなので`true`になる．

`StringComparison.Ordinal`を指定して比較することもできる．

```csharp
Console.WriteLine(
    left.Equals(right, StringComparison.Ordinal)
);
```

## 詰まったこと・分からなかったこと・知らなかったこと

- null警告に対して，単に`!`で警告を消すのではなく，型やnullチェックを実際の設計に合わせて修正する必要があること
- `is { Length: > 0 }`でnullチェックとプロパティの条件を同時に確認できること
- `[NotNullWhen(true)]`を使ってメソッドの戻り値とnull状態の関係をコンパイラに伝えられること
- `required`を使ってオブジェクト作成時のプロパティ指定を必須にできること
- `string`と`String`が同じ型であること
- stringが不変でも変数への再代入はできること
- `StringBuilder`が`System.Text`にあるクラスであること
- `StringBuilder`は中身を変更しながら文字列を組み立てられること
- C# 13以降では`\e`でESC文字を表現できること
- 未加工文字列では`"`や`\`をエスケープせずに記述できること
- 未加工文字列の終了区切りの位置によってインデントが決まること
- `$"""`で未加工文字列と文字列補間を組み合わせられること
- `Console.WriteLine()`を引数なしで呼ぶと改行だけを出力できること
- stringは参照型だが`==`では文字列の内容を比較すること
