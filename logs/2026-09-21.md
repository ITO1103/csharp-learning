## 学んだこと

### static / using static

`static`を付けたメンバーは，オブジェクトを`new`して作成しなくても型そのものから使用できる．

```csharp
Math.Pow(2, 3);
```

また，

```csharp
using static System.Math;
```

と書くことで

```csharp
Pow(2, 3);
```

のようにstaticメンバーを使用するときの型名も省略できる．

### ファイルベースアプリのディレクティブ

ファイルベースアプリでは，`#:`から始まるビルドシステムディレクティブを利用できる．

```csharp
#:package Spectre.Console@*
```

のように書くことでNuGetパッケージを追加できる．

### プリプロセッサディレクティブ

`#if`を使用すると，コンパイル時に定義されているシンボルによってコンパイル対象を変更できる．

```csharp
#if DEBUG
    Console.WriteLine("Debug");
#else
    Console.WriteLine("Release");
#endif
```

ファイルベースアプリでも，

```bash
dotnet run --file ConditionalCompilation.cs --configuration Release
```

のようにビルド構成を変更して確認できる．

```csharp
#if NET10_0_OR_GREATER
```

のように，ターゲットとする.NETのバージョンによって条件を分けることもできる．

`#pragma warning disable`と`#pragma warning restore`を使用すると，指定した範囲だけ特定のコンパイラ警告を無効化できる．

```csharp
#pragma warning disable CS0168
catch (FileNotFoundException ex)
#pragma warning restore CS0168
```

### 名前空間とプログラムの編成

名前空間とディレクトリ構成は別の仕組みだが，対応させることでコードを探しやすくできる．

```text
Services/Payments/PaymentService.cs
```

に対して，

```csharp
namespace MyApp.Services.Payments;
```

のようにする．

また，名前空間は型の種類ごとではなく，機能ごとに整理することが推奨されている．

```text
MyApp.Payments
MyApp.Inventory
MyApp.Services
```

などのように機能単位で分ける．

### interface

interfaceは「この型はこの機能を持つ」という契約を定義するもの．

```csharp
public interface IPaymentProcessor
{
    bool ProcessPayment(decimal amount);
}
```

これを実装するclassでは，定義されたメンバーを実装する必要がある．

```csharp
public class CreditCardProcessor : IPaymentProcessor
{
    public bool ProcessPayment(decimal amount)
    {
        return true;
    }
}
```

C#ではinterface名の先頭に`I`を付けるのが一般的な命名規則．

### アクセス修飾子とアセンブリ

ここで言うアセンブリは，プロジェクトをコンパイルして生成される`.dll`や`.exe`などの単位．

- `public`：他のアセンブリからもアクセス可能
- `internal`：同じアセンブリ内のみ
- `private`：その型の内部のみ

外部に公開する必要があるものだけ`public`，内部実装は`internal`や`private`にすることで，外部から触れる範囲を制限する．

```csharp
public class InventoryService
{
    public int GetStockLevel(string productName)
        => StockDatabase.Lookup(productName);
}

internal static class StockDatabase
{
}
```

この場合，`InventoryService`が外部向けの窓口となり，内部で`StockDatabase`を呼ぶ．

### 最上位レベルのステートメント

最上位レベルのステートメントを使用すると，明示的に`Main`メソッドを書かなくてもプログラムを実行できる．

コンパイラが内部でエントリポイントを生成するため，

```csharp
Console.WriteLine("Hello");
```

だけでも実行できる．

また，`args`も自動的に利用できる．

```csharp
foreach (var arg in args)
{
    Console.WriteLine(arg);
}
```

最上位レベルのステートメントを使用している場合，自分で`Main`メソッドを書くことはできるが，その`Main`はエントリポイントにはならない．

同じファイル内に型や名前空間を定義する場合は，最上位レベルのステートメントより後に記述する．

### awaitとTask

`Task`は「今すぐには完了しない処理」を表す．

```csharp
await Task.Delay(5000);
```

では，`Task.Delay()`がTaskを返し，`await`でその完了を待つ．

`Async`は非同期処理を行うメソッドに付ける一般的な命名規則．

`Main`内で`await`を使用する場合は，

```csharp
static async Task<int> Main(string[] args)
```

のように`async`と`Task`または`Task<int>`を使用できる．

### 組み込み型とカスタム型

C#には`int`，`double`，`bool`，`char`，`string`などの組み込み型がある．

また，自分で以下のような型を定義できる．

- class
- struct
- record
- record struct
- interface
- enum

用途によって，

- 一時的に値をまとめる：tuple
- 小さな値として扱う：struct / record struct
- データ中心：record
- 状態や処理を持つ：class
- 共通の契約：interface
- 固定された選択肢：enum

のように使い分ける．

### 値型と参照型

値型は代入すると値そのものがコピーされる．

```csharp
var point1 = new Coords(3, 4);
var point2 = point1;
```

一方，参照型では参照がコピーされ，同じオブジェクトを参照する．

```csharp
var list1 = new List<int> { 1, 2, 3 };
var list2 = list1;
```

### コンパイル時の型と実行時の型

変数として宣言されている型と，実際に参照しているオブジェクトの型が異なる場合がある．

```csharp
object boxed = "This is a string at run time";
```

この場合，

```text
コンパイル時の型：object
実行時の型：string
```

となる．

同様に，

```csharp
IEnumerable<char> characters = "abcdefghijklmnopqrstuvwxyz";
```

では，

```text
コンパイル時の型：IEnumerable<char>
実行時の型：string
```

となる．

### システム固有サイズの整数

`nint`と`nuint`は実行環境のポインタサイズに合わせてサイズが変わる整数型．

64bit環境では8byteになる．

```csharp
Console.WriteLine(IntPtr.Size);
```

現在のARM64環境では8byteであることを確認．

### 文字列リテラル

`$"..."`では文字列補間ができる．

```csharp
string message = $"Found {count} items";
```

`@"..."`では`\`をエスケープせずに書ける．

```csharp
string path = @"C:\Users\docs\file.txt";
```

`"""..."""`では生文字列リテラルを使用でき，JSONなどを(ほぼ)そのまま記述できる．

```csharp
string json = """
    {"name": "Alice", "age": 30}
    """;
```

### default

`default`は型ごとの既定値を表す．

```text
int     → 0
bool    → false
string? → null
```

ジェネリックでは`default(T)`のように，型に応じた既定値を取得できる．

### var

`var`は初期値からコンパイラが型を推論する．

```csharp
var name = "C#";
```

型が右辺から明らかな場合に使用すると，型名の重複を減らせる．

```csharp
var scores = new Dictionary<string, List<int>>();
```

### ターゲット型のnew式

左辺などから生成する型が分かる場合，`new`の後ろの型名を省略できる．

```csharp
List<string> names = new() { "Alice", "Bob", "Charlie" };
```

これは，

```csharp
List<string> names = new List<string>() { "Alice", "Bob", "Charlie" };
```

と同じ．

### dynamic

`dynamic`を使用すると，コンパイル時の型チェックを実行時まで遅らせることができる．

```csharp
dynamic value = 42;
value = "Now I'm a string";
```

実行時の値によって実際の型が変わるが，コンパイル時の型安全性が弱くなるため，必要な場合に使用する．
